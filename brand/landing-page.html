Four agents, one request

Each agent does one job and shows its work.

They read in parallel, and later agents build on what earlier ones found. None of them can approve anything.

Extraction

Finds the table, whatever the layout.

Matches columns by header in several languages, splits stacked tables, and flags every number it cannot read instead of guessing. A model is consulted only when your organization allows it, and its answer is checked against the file.

Soll / Haben → Debit / Credit

Validation

Eleven checks before a human looks.

Balance, duplicate accounts, signs, missing periods and more. Each finding points at the row it came from.

debits ≠ credits · account 4000 appears twice

Documents

Reads letters and PDFs, quotes the source.

Pulls dates, parties and amounts from Word, PDF and text files. A fact only appears if it can be found in the document itself.

"as of 31 December 2025" · p. 2

Reconciliation

Compares what different files say.

Sets a trial balance against the letters in the same request and flags amounts that do not match, directions that flip and currencies that disagree.

How a request moves

From a question to an approved dataset.

  1. Request

    A manager asks each entity for what is needed, with a due date.

  2. Upload

    Contributors add files. Anything unsafe or unreadable is refused with a reason.

  3. Agents read

    Extraction, validation, documents and reconciliation run and attach findings.

  4. Person decides

    A reviewer approves, edits or sends it back. Every AI result needs one.

  5. Export

    Approved data leaves as a pack, with who approved what and when.

Audit trail

Change one entry and the chain breaks.

Every action is recorded with the one before it folded in. Export the log and verify it yourself, with nothing but a hash function. If someone edits history, the check fails at the exact entry.

Built to be checked

Safe by structure, not by promise.

Each tenant sees only its own data

Isolation is enforced by the database itself, so a bug in the app cannot read across customers.

Nothing goes out without a limit

External AI calls are capped per file, per prompt and per day, and an admin can turn them off entirely.

Hostile files stop at the door

Files are checked by content, not name. Disguised programs, scripts and oversized archives are refused.

Where it stands. Pelloria is a working prototype running on fictional data. It has been through a structured security review and automated test suites, but not an external penetration test, and sign-in has been tested against a mock identity provider only.
